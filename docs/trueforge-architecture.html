TrueForge architecture overview

CampaignForge turns a brief into approved, publishable campaign work.

The repository combines a TrueForge parent agent, two private specialist agents, a CampaignForge MCP service for campaign production, and a separate LinkedIn OAuth MCP service for human-gated social publishing.

Agent architecture inside TrueForge

campaignforge

User-facing parent agent. It keeps IDs and implementation details in Agent steps while chat stays focused on campaign decisions and results.

  • assess_campaign_intake
  • create_campaign_plan
  • approve_campaign_concept
  • delegates approved execution

CampaignForge Planner

Private dynamic child that asks decision-critical intake questions and returns an audience insight, claim boundary, platform plan, and three routes.

  • Product hero
  • Audience moment
  • Benefit proof

CampaignForge Executor

Private dynamic child that turns the approved route into a production-ready image brief and distinct platform captions.

  • generate_image
  • get_platform_copy_guidance
  • inline campaign asset and copy

LinkedIn publishing path

A separate connector used when approved campaign copy and media become a LinkedIn draft and then a real post.

  • OAuth connection
  • draft and review
  • explicit publish approval

End-to-end campaign flow

1
IntakeUser supplies product, objective, audience, platforms, and constraints. Orchestrator calls assess_campaign_intake.
2
PlanningPlanner receives a self-contained brief and returns three routes. Parent persists them with create_campaign_plan.
Selection gate: no image generation occurs until the user clearly chooses one route.
3
ApprovalOrchestrator maps a natural-language choice to the selected concept and calls approve_campaign_concept.
4
ProductionExecutor creates a production brief, calls generate_image, requests platform copy guidance, and returns the PNG plus captions.
5
LinkedIn draftAgent checks OAuth, stages media under linkedin-mcp-server/generated/, and calls create_linkedin_draft.
Publication gate: exact draft text, image, and version must be reviewed and approved by a human.
6
PublishAgent calls approve_linkedin_draft, waits for a separate explicit request, then calls publish_linkedin_draft and reports status.

Credential boundary: keep provider keys and LinkedIn secrets in each MCP service's local .env. Never put secrets in TrueForge skills, prompts, committed fixtures, or browser-visible chat.

Run it locally

CampaignForge MCP

cd /path/to/ad-campaign
cp .env.example .env
npm install
npm run dev

Default endpoint: http://127.0.0.1:8788/mcp.

LinkedIn MCP

cd linkedin-mcp-server
cp .env.example .env
npm install
npm run build
npm start

Open http://localhost:8810/oauth/linkedin/start, then add http://127.0.0.1:8810/mcp as a no-auth local connector.
